<objective>
Widen the vendored Inter subset to cover **latin-ext**, so `č`, `ę`, `ü`, `å`, `ł`, `ș` stop falling
back mid-string inside exported PNGs.

Purpose: `04-11` makes creator-typed text the most visible element on the map, and this product's
users are making maps **of** the countries whose names carry those glyphs. `04-CONTEXT.md` D4-15
calls silent mid-string fallback "not acceptable" for exactly that reason.

The measured answer is **two `@font-face` rules for one family, each with its own `unicode-range`**.
`04-RESEARCH.md § latin-ext` proved this parses and renders through the export path (a two-face
inline `<style>` produced ink 2,167 — byte-identical to the single-face control — at a serialised URL
length of 137,987 characters). Google Fonts always splits by `unicode-range`, so a single file
covering latin **and** latin-ext is not obtainable from it, and producing one needs a subsetting
toolchain that is **measured absent on this machine** (`pyftsubset`, `fonttools`, and
`woff2_compress` are all not found). The two-face route needs none of it.

Output: a second vendored woff2, a second README asset row verified by live fetch, a two-face builder,
a matching editor `@font-face`, and an e2e gate that proves the embedded faces are what draw the glyphs.
</objective>
